# hxyfront-62009 地毯修复纹样档案

源提示词编号：2

做一个给手工地毯修复工作室使用的纹样与修复档案前端项目，可以记录地毯产地、年代、结密度、材质、染色类型、破损区域、补线颜色和修复工序。页面需要有纹样局部标记图、修复前后记录、材料色卡、工序进度和按产地筛选的档案列表。

## 技术栈

React + Vite + TypeScript

## 本地运行

```bash
npm install
npm run dev
```

开发端口：62009

## 续作修订账（离线合并机制）

库房断网时，修复师在平板记录破损区域、补线色卡与工序；回网后按「档案键 + 字段」并回总档。

- **字段级合并**：所有改动以操作流水（opId 幂等键）记入修订账，按 `地毯编号/色卡号 + 字段` 合并，而非整条覆盖。
- **冲突留两版**：同一字段两边都改过（服务端修订 > 客户端基线且值不同）→ 两版均置「待确认」，不覆盖，人工选择采用本地/服务端版后两版留档可追溯。
- **色卡级联作废**：色卡过期或适用范围收窄 → 关联工序立即「作废」、修复前后记录置「待重算」；复检延期通过后，已勾工序恢复「已完工」（仍能完工），其余恢复进行中；一键重算为作废工序重新匹配当前有效色卡。
- **断点续传 + 幂等**：上传逐条确认并落盘 checkpoint；弱网中断后已完成部分留住，恢复后只补未完成项；同一 opId 重复提交服务端去重，不生成第二份记录。

演示：同步条可「模拟断网 / 恢复网络」「弱网模式」；断网时编辑会进离线草稿箱，回网后点「上传/补传」；「重复提交演示」用同一批 opId 再提交一次，全部命中幂等去重。

## 技术栈

React + Vite + TypeScript（无后端，总档/平板状态均持久化在 localStorage，同步逻辑为本地模拟）
